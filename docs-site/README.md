# 감시 신청 페이지

`index.html` 하나짜리 정적 페이지다. 서버도, 빌드도, 의존성도 없다.

## 무엇을 하는가

전시·렉처 두 프로그램을 **완전히 독립된 달력**으로 보여준다. 각 달력은
`data/availability.json`(감시 워크플로가 매 틱마다 커밋하는, 그 달 실제
매진/여석 현황)을 읽어 진짜 상태를 그린다 — 요일 규칙 같은 추측이 아니다.
날짜를 누르면 그 날짜의 실제 회차가 펼쳐지고, 고른 것은 미리 채워진 GitHub
이슈 주소로 넘어간다. 이슈가 감시 목록이자 알림 채널이므로, 이 페이지가 직접
들고 있어야 할 상태가 없다 — 토큰도, 로그인도, 백엔드도 필요 없다.

## 어디에 올려져 있는가

**GitHub Pages가 1차 배포처다.** 아래 주소가 이 시스템의 정식 제품 URL이며,
Claude 아티팩트 미리보기는 개발 중 확인용 사본일 뿐이다.

| 주소 | 성격 | 자동 등록 |
|---|---|---|
| **https://khrias86-oss.github.io/audium-reservation/** | 1차 배포처. 아래 "켜는 법" 참고 — **아직 저장소 설정에서 켜지지 않았다** | ✅ 켜지면 정상 작동 |
| https://claude.ai/code/artifact/1af3e850-4a59-4c2d-8501-39bb6548f72a | 개발 중 확인용 사본. 소유자만 열린다 | ❌ 미리보기 CSP가 `fetch`를 막는다 |

### Pages 켜는 법 (한 번만, 사람이 직접)

1. 저장소 **Settings → Pages**
2. **Build and deployment → Source** 를 **GitHub Actions** 로 변경
3. `.github/workflows/pages.yml`을 한 번 실행 (Actions 탭 → `Run workflow`,
   또는 `docs-site/`가 바뀌는 다음 커밋을 그냥 기다려도 된다)

Actions의 기본 토큰(`GITHUB_TOKEN`)에는 Pages **사이트를 새로 만들** 권한이
없다 — 이미 켜진 Pages에 **배포할** 권한뿐이다(`Resource not accessible by
integration`). 저장소 설정을 바꾸는 일이라 봇에게 열어두지 않는 것이고, 그
자체가 합리적인 선이라 워크플로 쪽에서 우회하지 않는다. 켠 뒤로는
`docs-site/`가 바뀔 때마다 자동으로 재배포된다.

### 왜 미리보기에서는 자동 등록이 안 되는가

Claude 아티팩트(미리보기) 페이지는 보안 정책(CSP)으로 `api.github.com`을 포함해
임의의 외부 서버로 나가는 `fetch`를 전부 막는다. 토큰을 넣고 "연결하기"를 누르면
`TypeError: Failed to fetch`가 나는데, 이건 인터넷 문제가 아니라 이 차단이다.
`connect()`가 이 경우를 감지해 정확한 안내를 준다 (`looksLikePreview()`).

**신청서를 하나씩 눌러 등록하는 방식**(`window.location.href`로 GitHub 이슈 작성
화면을 여는 것)은 `fetch`가 아니라 페이지 이동이라 CSP의 영향을 받지 않는다.
그래서 미리보기에서도 그대로 동작한다 — 감시 자체는 막히지 않는다.

**브랜치 배포를 쓰지 않은 이유**는 그 방식이 루트나 `/docs` 두 곳만 고를 수
있기 때문이다. 이 저장소의 `docs/`는 이미 설계 문서가 쓰고 있어서, 문서를
옮기거나 섞는 대신 Actions로 올린다 — 폴더 제약이 없다.

### 페이지가 공개되어도 안전한 이유

저장소가 public이므로 이 페이지도 누구나 열 수 있다. 그래도 문제가 없는 것은
**페이지가 비밀을 하나도 담고 있지 않기** 때문이다.

- GitHub 토큰은 파일에 없다. 사용자가 자기 브라우저에 직접 넣고, `localStorage`에만
  남으며, `api.github.com` 외에는 나가지 않는다
- "내 예약 정보"(이름·이메일·휴대폰)도 마찬가지로 브라우저에만 있다
- 남의 브라우저에서 이 페이지를 열어도 할 수 있는 일은 **자기 토큰으로 자기가
  권한을 가진 저장소에 이슈를 만드는 것**뿐이다

## 고칠 때 주의할 것

- `REPO` 상수가 이슈 주소를 만든다. 저장소 이름이 바뀌면 여기도 바꾼다.
- 달력은 **회차나 운영 요일을 하드코딩하지 않는다.** `data/availability.json`을
  그대로 그릴 뿐이다 — 그 파일은 `src/adapters/audeum/build-snapshot.ts`가
  정찰로 실측한 것(`docs/site-contract.md`)만 써서 만든다. 사이트가 회차나
  운영 요일을 바꾸면 그쪽만 고치면 되고, 이 페이지는 손댈 필요가 없다.
- `issueBody()`의 "관람 종류" 문구(`KIND_TEXT`)는 `src/config/watch-requests.ts`의
  `productText.includes('렉처')` 판별과 짝이다. 한쪽만 고치면 렉처 신청이
  조용히 전시로 잘못 분류된다 (실제로 한 번 있었던 버그 — PR #19).
- 신청서를 **자동으로 여러 개 열지 않는다.** 그렇게 하면 첫 건에서 현재 창이
  넘어가며 나머지가 사라지거나 팝업 차단에 걸리고, 사용자는 빠진 줄 모른다.
